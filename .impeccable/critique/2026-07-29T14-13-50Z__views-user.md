**Design Specificity Verdict**

The high-visibility surfaces (dashboard with drag-to-folder, xterm console with prompt masking, real-time stat WebSockets) are genuinely authored for this product. The deep surfaces (settings, account, startup) are stock admin-panel patterns — interchangeable with any CRUD app. The modal system, toast system, and sidebar nav follow Pterodactyl/pelican conventions without meaningful differentiation.

**LLM assessment**: The product has authored moments (drag folders, prompt masking, daemon error states) but the baseline UI is category-interchangeable admin panel. The visual system (neutral grayscale, indigo accent, rounded-xl) is executed competently but without distinction.

**Overall Impression**

Airlink Panel's user-facing pages are functional and built on a solid CSS-variable theming architecture, but the execution has significant surface-level inconsistency. The most urgent problems are behavioral (page reloads on every file op destroying user state, duplicated desktop/mobile layouts that will drift) rather than visual. Fixing these behavioral issues will have more impact than any cosmetic change.

**What's Working**

1. **Dashboard drag-to-folder interaction** — Tactile, responsive, visually confirmed. The ghost element, folder popup, and delete-with-reassurance copy ("Servers inside will stay accessible") show careful design thinking.

2. **Real-time console with prompt masking** — ANSI-aware WebSocket stream, exponential backoff reconnect, touch scroll handling, and themed color scheme. Production-quality terminal UX.

3. **Error state coverage** — Daemon offline, server suspended, installation in progress, and server limit are all handled with distinct, visually consistent alerts with retry actions.

**Priority Issues**

**[P0] Page reload after every file operation**
- **What:** Every file op (create, rename, delete, upload, archive, extract) ends with `setTimeout(() => location.reload(), 800)` — see files.ejs:538, 695, 737, 840, 1026.
- **Why it matters:** Destroys scroll position, selection state, and search/filter. Makes file manager feel like a 2005 web app. Users managing many files hit this dozens of times per session.
- **Fix:** Use fetch for operations, then DOM-manipulate the table row instead of reloading. Preserve search/filter state.
- **Suggested command:** `$impeccable polish views/user/server/files.ejs`

**[P0] Duplicated desktop/mobile layout in manage.ejs**
- **What:** Lines 80-246 (desktop) and 251-398 (mobile) are two complete, independent page layouts. Sidebar, header, alerts, controls, stats, and terminal are all duplicated.
- **Why it matters:** Every change must be made twice. These will drift. Already diverging: mobile lacks ghost-text autocomplete, uses different pixel values for borders.
- **Fix:** Single responsive layout with CSS grid/flex reordering. Use `lg:hidden`/`hidden lg:block` on specific elements, not entire page shells.
- **Suggested command:** `$impeccable adapt views/user/server/manage.ejs`

**[P1] Inline style proliferation against design system**
- **What:** dashboard.ejs uses 48 inline `style` attributes. files.ejs uses 56. Settings use Tailwind classes. Three different radii for equivalent modals (`rounded-2xl`, `rounded-[14px]`, `rounded-xl`).
- **Why it matters:** Inline styles bypass CSS caching, make theming fragile. Guarantees inconsistency as the app grows.
- **Fix:** Create CSS utility classes for repeated patterns (`.al-stat-box`, `.al-section-label`, `.al-muted-text`). Use `@apply` in the CSS layer.
- **Suggested command:** `$impeccable extract views/user/`

**[P1] No unsaved changes protection on forms**
- **What:** Settings, account, startup forms have no `beforeunload` protection. Clicking a nav link or closing the tab with unsaved data loses it silently.
- **Why it matters:** Users configuring server settings are doing real work. Losing 15 minutes of form data erodes trust entirely.
- **Fix:** Add shared `beforeunload` listener and dirty-form tracking in `header.ejs` or as a shared script.
- **Suggested command:** `$impeccable harden views/user/server/settings.ejs`

**[P2] Inaccessible scrollbar removal**
- **What:** `::-webkit-scrollbar { display: none; }` and `scrollbar-width: none` applied globally (header.ejs:31-32).
- **Why it matters:** Scrollable regions without visible scrollbars fail WCAG 2.1 SC 2.1.1. Users can't tell an area is scrollable.
- **Fix:** Use `scrollbar-width: thin` instead of hiding entirely.
- **Suggested command:** `$impeccable audit`
