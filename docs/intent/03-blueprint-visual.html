Service Blueprint: Airlink Panel
Frontstage Administrator (fleet operator)
1
Login / 2FA
2
Overview: health at a glance
3
Manage nodes, servers, users, images, addons
4
Create node (out-of-band daemon install)
5
Provision server → verify online
Line of interaction · HTTPS · single browser surface
Frontstage Server owner / subuser (single-server operator)
1
Dashboard: status + resource usage
2
Console: live terminal + power
3
Files, backups, schedules, databases
4
Startup vars, settings, subusers
5
Incident: diagnose → fix → verify
Line of visibility
Backstage Express control plane
Middleware chain
session (Prisma store) · nonce + CSP strict-dynamic · IP-ban · rate-limit · CSRF (skipped for /ws + /api) · translation
Module router
auth · core · user · admin · api (v1 + client) · permission wildcards
Addon loader
import() per addon · version-gated · routes + views + UI registration
WS gateway
/console · /status · /events · /online-check · WS token auth
Ops services
S3 backup upload · SMTP mailer · analytics aggregation · search index
Data store
Prisma · SQLite (default) / MySQL · sessions · settings · servers · users
Line of support
Support per-node daemons + infrastructure
Daemon (per node)
HMAC-signed RPC · Docker containers · files · SFTP
Docker
container lifecycle · images · networks
Registries
Docker Hub images · Modrinth (addon) · S3 backups
Deployment
systemd · reverse proxy · node OS

Fail points: panel↔daemon handshake (manual, out-of-band) · addon UI divergence · SQLite scaling ceiling · CSP nonce vs. addon inline JS.
