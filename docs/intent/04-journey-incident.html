Journey: Recover from Failure

Incident flow. Lead with state, never strand the operator, always give a recovery action.

Flow: Incident (owner or admin)
⚠
Notice: server down
dashboard card · status pill + label (never color-only)
1
Open console
state leads: online / offline / starting / suspended
2
Diagnose
log tail surfaced · last-known failure reason as status line
3
Act
start / restart one tap · reinstall gated + double-confirmed
4
Verify
status transitions · console auto-scrolls to boot output
5
Resolved
online confirmed in console + dashboard
Daemon unreachable?
banner: name it · retry · out-of-panel hint
Container crashed?
exit code / OOM surfaced · reinstall offered inline
Never a dead end · every failure names the state, the cause, and a recovery action
Flow: Degraded path (daemon offline) — Tier-1 degradation
◉
Page loads
console / files / backups / status
1
Inline offline banner
"Daemon connection lost" + Retry
2
Explain the boundary
what works (cached) · what's blocked (console, writes)
3
Give an exit
retry in-panel · honest out-of-panel hint (node daemon service)
4
Recover or leave informed
never a spinner, never a silent failure
Tier 0 keeps working · auth, dashboard, account degrade only if the DB is down
